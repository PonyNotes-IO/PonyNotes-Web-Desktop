# 苹果内购商品映射：直接在现有套餐管理页配置

## 映射规则（按你的设计）

- 商品 ID = `苹果商品前缀` + `.` + `billingType`，billingType 枚举仅 `monthly` / `yearly`
- 前缀存在套餐表上，每个套餐一个（如 standard 配 `com.xmbj.ponynotes.pro`，team 配 `com.xmbj.ponynotes.team`；只有一套餐时效果即单一固定前缀 `com.xmbj.ponynotes.pro`）
- 前缀留空的套餐 = 不参与苹果内购
- 不新建表、不新建菜单页面，全部在 `/xmbj/plans`（manager.xiaomabiji.com 后台 → 订阅套餐）里调整

## 1. 数据库变更（追加到 sql/apple_iap.sql 或新文件 sql/apple_iap_plan_prefix.sql）

```sql
ALTER TABLE af_subscription_plans
    ADD COLUMN apple_product_prefix varchar(128) DEFAULT NULL; -- 苹果内购商品ID前缀，空=不走内购
COMMENT ON COLUMN af_subscription_plans.apple_product_prefix IS '苹果内购商品ID前缀，商品ID=前缀.monthly/.yearly';
CREATE UNIQUE INDEX uk_plans_apple_prefix ON af_subscription_plans(apple_product_prefix) WHERE apple_product_prefix IS NOT NULL;
```

## 2. 后端改动

- `AfSubscriptionPlans` domain 增加 `appleProductPrefix` 字段（含 getter/setter）
- `AfSubscriptionPlansMapper.xml`：resultMap / insert / update / select 列表加上该列；新增查询 `selectByAppleProductPrefix(prefix)`
- `IAfSubscriptionPlansService` + impl 增加对应方法（注意 impl 已是 `@DataSource(SLAVE)`，沿用）
- `AfSubscriptionPlansController` 无需新接口——现有 add/edit 原样保存新字段
- `AppleIapServiceImpl.processTransaction`：删除 `appleIapConfig.getProducts()` 映射逻辑，改为：
  1. 从商品 ID 剥离 `.monthly` / `.yearly` 后缀得到前缀（无合法后缀直接拒绝）
  2. `selectByAppleProductPrefix` 查套餐（未配置/套餐未启用则拒绝）
  3. billingType = 后缀本身，planId = 命中套餐 id；金额、落库、发货逻辑不变
- `AppleIapConfig` 删除 `products` 结构；`application.yml` 删除 `payment.apple.products` 块并加注释「商品映射在套餐管理中配置」

## 3. 前端改动（现有套餐页增强）

`ruoyi-ui/src/views/xmbj/plans/index.vue` + 无需动 `api/xmbj/plans.js`（字段随 form 提交）：

- 编辑/新增弹窗增加一项「苹果内购商品前缀」：`el-input`，placeholder 示例 `com.xmbj.ponynotes.pro`，校验规则（可空；非空时正则 `^[a-z0-9]+(\.[a-z0-9]+)+$` 且不允许以 `.monthly`/`.yearly` 结尾）
- 旁边实时预览生成的两个商品 ID（`前缀.monthly` / `前缀.yearly`，只读展示），管理员照抄到 App Store Connect 建商品
- 列表页加一列「苹果商品ID」显示两个生成值（空则显示 -）

## 4. 实施与验证顺序

1. 执行 ALTER SQL（业务从库）
2. 后端改动 → `mvn compile` 通过
3. 前端改动 → ruoyi-ui 编译通过
4. 验证：后台给 standard 套餐填前缀 → 沙箱交易/单测确认 verify 能按 `前缀.monthly` 反查套餐并开通

## 兼容说明

- verify/restore/回调接口对外行为不变；`sys_payment_order.apple_product_id` 仍存完整商品 ID
- 上线后需在后台为要走内购的套餐各填一次前缀（原来 yml 里的示例映射作废）
