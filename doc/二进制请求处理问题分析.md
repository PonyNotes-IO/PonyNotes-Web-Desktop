# 二进制请求处理问题分析

## 一、问题概述

`/api/scenes/v2/post` 接口用于上传加密画布的二进制数据，前端通过 `fetch` API 发送 `ArrayBuffer` 类型的请求体。该接口在处理过程中出现了多种错误，最终通过修改过滤器链和请求包装器解决。

## 二、报错类型汇总

| 错误类型 | 错误信息 | 产生阶段 |
|----------|----------|----------|
| `EOFException` | `Length to read: 792 actual: 0` | Controller 读取请求体时 |
| `Character decoding failed` | Parameter name contains invalid UTF-8 | Tomcat 表单参数解析时 |
| `RequestRejectedException` | parameter name is not allowed | Spring Security 防火墙校验时 |
| 400 Bad Request | `{"error":true,"message":"Empty payload"}` | Controller 返回空数据 |

## 三、根本原因分析

### 3.1 请求体只能读取一次

Servlet 规范中，`HttpServletRequest.getInputStream()` **只能读取一次**。读取后流的位置到达末尾，再次读取将返回空数据。

### 3.2 自动表单参数解析

当请求的 `Content-Type` 为 `application/x-www-form-urlencoded`（前端未设置 Content-Type 时的默认值），Spring/Tomcat 会自动尝试解析表单参数：

```
请求体：[二进制数据...]
         │
         ▼
┌─────────────────────────────────────────────────────┐
│  Tomcat/Spring 自动调用 getParameterMap()           │
│  └── 内部调用 getInputStream() 读取请求体           │
│       └── 流被消费，位置到达末尾                     │
└─────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────┐
│  Controller 调用 IOUtils.toByteArray(request.getInputStream()) │
│  └── 从流的末尾开始读取，返回 0 字节                 │
│       └── "Empty payload" 错误                      │
└─────────────────────────────────────────────────────┘
```

### 3.3 原始代码缺陷

**问题1：`IOUtils.readFully()` 的严格要求**

```java
// 原始代码（有问题）
byte[] data = IOUtils.readFully(request.getInputStream(), request.getContentLength());
```

`readFully()` 要求必须读取指定长度的字节，否则抛出 `EOFException`。

**问题2：`RepeatableFilter` 只处理 JSON 请求**

```java
// 原始代码（有问题）
if (StringUtils.startsWithIgnoreCase(request.getContentType(), MediaType.APPLICATION_JSON_VALUE)) {
    requestWrapper = new RepeatedlyRequestWrapper((HttpServletRequest) request, response);
}
```

二进制请求的 Content-Type 不是 `application/json`，不会被包装。

**问题3：`RepeatedlyRequestWrapper` 不支持二进制数据**

```java
// RepeatedlyRequestWrapper.java 第30行
body = HttpHelper.getBodyString(request).getBytes(Constants.UTF8);
```

通过 UTF-8 字符串转换缓存数据，会损坏包含 null 字节和无效 UTF-8 序列的二进制数据。

## 四、解决方案

### 4.1 新增 BinaryRepeatedlyRequestWrapper

创建二进制安全的请求包装器，直接缓存原始字节：

**文件路径**: `ruoyi-common/src/main/java/com/ruoyi/common/filter/BinaryRepeatedlyRequestWrapper.java`

```java
public class BinaryRepeatedlyRequestWrapper extends HttpServletRequestWrapper {
    
    private final byte[] body;

    public BinaryRepeatedlyRequestWrapper(HttpServletRequest request) throws IOException {
        super(request);
        body = IOUtils.toByteArray(request.getInputStream());  // 直接读取原始字节
    }

    @Override
    public ServletInputStream getInputStream() throws IOException {
        final ByteArrayInputStream bais = new ByteArrayInputStream(body);  // 返回新的流
        return new ServletInputStream() {
            @Override
            public int read() throws IOException {
                return bais.read();
            }
            // ...
        };
    }
}
```

**设计要点**：
- 构造函数中立即读取所有字节到内存缓冲区
- 每次调用 `getInputStream()` 返回新的 `ByteArrayInputStream`
- 请求体可被多次读取而不会丢失数据

### 4.2 修改 RepeatableFilter

增加对 `/api/scenes/v2/post` 端点的判断，使用二进制安全包装器：

**文件路径**: `ruoyi-common/src/main/java/com/ruoyi/common/filter/RepeatableFilter.java`

```java
@Override
public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
        throws IOException, ServletException {
    if (request instanceof HttpServletRequest) {
        HttpServletRequest httpRequest = (HttpServletRequest) request;
        String contentType = httpRequest.getContentType();
        String requestUri = httpRequest.getRequestURI();
        
        boolean isJsonRequest = StringUtils.startsWithIgnoreCase(contentType, MediaType.APPLICATION_JSON_VALUE);
        boolean isBinaryShareRequest = requestUri.contains("/api/scenes/v2/post");
        
        if (isJsonRequest) {
            requestWrapper = new RepeatedlyRequestWrapper(httpRequest, response);
        } else if (isBinaryShareRequest) {
            requestWrapper = new BinaryRepeatedlyRequestWrapper(httpRequest);  // 二进制请求使用专用包装器
        }
    }
    chain.doFilter(requestWrapper != null ? requestWrapper : request, response);
}
```

### 4.3 修改 SceneController

**文件路径**: `ruoyi-admin/src/main/java/com/ruoyi/web/controller/tool/SceneController.java`

**构造函数增加目录创建**：
```java
public SceneController() {
    try {
        Files.createDirectories(Paths.get(STORAGE_DIR));
        Files.createDirectories(Paths.get(SHARE_DIR));  // 新增：创建分享目录
    } catch (IOException e) {
        log.error("Failed to create storage directories", e);
    }
}
```

**createShare 方法**：
```java
@PostMapping("v2/post")
public ResponseEntity<?> createShare(HttpServletRequest request) {
    try {
        String id = UUID.randomUUID().toString().replace("-", "");
        byte[] data = IOUtils.toByteArray(request.getInputStream());
        
        if (data.length == 0) {
            return ResponseEntity.badRequest().body("Empty payload");
        }
        
        Path filePath = getSharePath(id);
        Files.write(filePath, data);
        
        Map<String, Object> result = new HashMap<>();
        result.put("id", id);
        return ResponseEntity.ok(result);
        
    } catch (Exception e) {
        log.error("Failed to create share", e);
        return ResponseEntity.internalServerError().body(e.getMessage());
    }
}
```

**关键设计**：使用 `HttpServletRequest` 直接读取，避免 `@RequestBody` 触发额外的参数解析机制。

## 七、注意事项

### 7.1 Content-Type 问题

前端发送 `ArrayBuffer` 时，浏览器可能不设置 `Content-Type` 头或默认使用 `application/x-www-form-urlencoded`，这会触发 Tomcat 的表单参数解析。解决方案是在 Filter 层提前缓存请求体。

### 7.2 为什么不用 @RequestBody

使用 `@RequestBody` 时，Spring 的 `RequestResponseBodyMethodProcessor` 会调用 `getBody()`，而 `ServletServerHttpRequest.getBody()` 在处理 `application/x-www-form-urlencoded` 时会调用 `getParameterMap()`，触发 `StrictHttpFirewall` 对参数名的校验，导致二进制数据中的无效字符被拒绝。

### 7.3 内存使用

`BinaryRepeatedlyRequestWrapper` 将整个请求体缓存到内存中，对于超大文件上传可能存在内存压力。当前接口处理的是加密画布数据，数据量较小（通常 < 1MB），因此该方案是合理的。如果未来需要处理大文件，应考虑使用流式处理或分片上传。
