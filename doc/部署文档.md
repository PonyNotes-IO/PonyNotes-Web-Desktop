## 3. 后端服务（ruoyi-admin.jar）

### 3.1 本地构建

```bash
cd <repo根目录>
git checkout <待发布分支>          # 例如 feature_payment_260811
git pull

# 全量构建（多模块）
mvn clean package -Dmaven.test.skip=true
# 只构建后端及其依赖模块（更快）
mvn -pl ruoyi-admin -am clean package -Dmaven.test.skip=true

# 产物：ruoyi-admin/target/ruoyi-admin.jar（约 157MB fat jar）
```

注意事项：

- 支付/推送证书（`ruoyi-admin/src/main/resources/cert/` 下的微信 `apiclient_key.pem`、Apple `SubscriptionKey_*.p8` 等）已打进 jar，构建机必须存在这些文件；**这些文件不要提交到公开仓库**。
- 线上运行 profile 由服务器 `start.sh` 指定为 `server`，对应 `application-server.yml`：本机 MySQL（库 `ponynote_prod`）+ 本机 PostgreSQL（库 `xiaomabiji`）+ 本机 Redis。仓库里另有 `prod`（阿里云 RDS）、`druid`（开发默认）等 profile，勿混用。
- 打包前确认 `application.yml` 中 `payment.apple.enabled`、`payment.wechat.mch-id` 等支付配置与本次发布目标一致。

### 3.2 上传与发布

```bash
# 1) 上传新包到服务器临时目录
scp ruoyi-admin/target/ruoyi-admin.jar cloudweb@101.201.244.231:/tmp/ruoyi-admin.jar

# 2) 登录服务器
ssh cloudweb@101.201.244.231

# 3) 备份旧包（沿用现网 _YYMMDD 命名习惯）
cd /opt/cloudweb/server
cp -p ruoyi-admin.jar ruoyi-admin.jar_$(date +%y%m%d)

# 4) 替换
mv /tmp/ruoyi-admin.jar ./ruoyi-admin.jar

# 5) 重启（必须在 /opt/cloudweb/server 目录下执行！）
./start.sh
```

**关键注意事项：**

1. **必须在 `/opt/cloudweb/server` 目录下执行 `start.sh`**。程序工作目录决定了 `./data/scenes`、`./data/share`（白板场景与分享数据）和 `./logs` 的位置，在别的目录启动会在错误位置生成 `data` 目录，导致白板数据读写错乱。
2. `start.sh` 内含现网真实参数（`--spring.profiles.active=server`、短信/OSS 的 AccessKey、支付调试开关、Apple 商品前缀），**替换 jar 时不要改动 `start.sh`**。
3. Apple 支付切生产：打开 `start.sh` 中 `# ARGS="$ARGS --payment.apple.environment=PRODUCTION"` 的注释后重启（同时确认 `application.yml` 中 `payment.apple.enabled: true`、`product-prefix` 与 App Store Connect 一致）。
4. `start.sh` 逻辑是「`kill -9` 旧进程 → nohup 启动新进程」，重启期间约 10~30 秒接口不可用（JVM 启动 + 建连）。
5. `data/`（白板数据）、`logs/` 目录不要删除或整体覆盖；`data.SNAPSHOT_*` 为历史快照。
6. `/opt/cloudweb/pkgs/ruoyi-admin.jar` 是现网留存的同版本包副本（归档用），可选同步一份。

### 3.3 发布后验证

```bash

ss -lntp | grep 8080
ps -ef | grep ruoyi-admin.jar | grep -v grep

# 日志（启动异常首先看 nohup.out 末尾）
tail -n 100 /opt/cloudweb/server/logs/sys-info.log
tail -n 100 /opt/cloudweb/server/nohup.out

# 后端本机连通性
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/
```

外网验证：

- 管理后台 https://manager.xiaomabiji.com 能登录、菜单/接口正常（走 `/prod-api/`）。
- 官网 https://www.xiaomabiji.com 相关接口正常。
- 涉及支付改动时，抽查一笔小额/沙箱支付全链路。回调地址配置在 `application.yml` 的 `payment.*` 中：
  - 支付宝 `notify-url` / `return-url`、Apple `notify-url` 均为 `https://www.xiaomabiji.com/prod-api/api/payment/callback/...`，与 Nginx `/prod-api/` 反代规则匹配，可正常回调到后端。
  - ⚠️ **微信支付 `notify-url` 当前为 `http://www.xiaomabiji.com/api/payment/callback/wechat`，不带 `/prod-api/` 前缀**，而 www 站点的 Nginx 只反代 `/prod-api/`，该地址会被 `try_files` 回落到首页（拿不到微信通知）。本次发布如涉及微信支付，需先修正为 `https://www.xiaomabiji.com/prod-api/api/payment/callback/wechat`（或与运维确认服务器上的实际处理方式）后再验证。

### 3.4 数据库变更

- 增量 SQL 在 `sql/` 目录下，按本次发布内容选择性执行；执行库为本机 MySQL 8 的 `ponynote_prod`（账号密码见 `application-server.yml`）。
- 本分支（Apple 支付）对应 `sql/apple_iap.sql`：给 `sys_payment_order` 增加 3 个苹果内购字段及唯一索引；脚本含 `ALTER TABLE`，执行前确认该表未执行过，避免重复报错。
- 执行示例（在服务器上）：

```bash
mysql -h127.0.0.1 -u<账号> -p <库名> < apple_iap.sql   # 账号/库名见 application-server.yml
```

### 3.5 日志与运维提示（现状）

- 日志：`/opt/cloudweb/server/logs/sys-info.log`、`sys-error.log`（按天滚动，保留 60 天）；`sys-error.2026-*.log` 为历史归档。
- `/opt/cloudweb/server/nohup.out` 是控制台输出，目前已增长到约 186MB，可安全清空：`: > nohup.out`（不影响运行中的进程）。
- 后端**不是 systemd 托管**，服务器重启后需手动 `./start.sh`；如需开机自启建议由运维加 systemd 单元（需 root）。

### 3.6 回滚

```bash

cp -p ruoyi-admin.jar_YYMMDD ruoyi-admin.jar   # 换回上一版本
./start.sh
```

## 4. 管理后台（ruoyi-ui）

### 4.1 本地构建

```bash
cd ruoyi-ui
npm install            # 首次或依赖有变更时
npm run build:prod     # 产物：ruoyi-ui/dist/（含 .gz 预压缩文件）
```

注意事项：

- 生产接口前缀由 `.env.production` 的 `VUE_APP_BASE_API=/prod-api` 决定（同域反代），无需改代码；`vue.config.js` 里的 `baseUrl` 只影响本地 `npm run dev` 的代理目标。
- 若构建报 `ERR_OSSL_EVP_UNSUPPORTED`（Node 17+ 与 webpack4 的 OpenSSL 兼容问题）：
  - Windows cmd：`set NODE_OPTIONS=--openssl-legacy-provider && npm run build:prod`
  - Git Bash：`export NODE_OPTIONS=--openssl-legacy-provider && npm run build:prod`
  - 或改用 Node 16 构建。

### 4.2 上传与发布

```bash
# 1) 本地打包并上传
tar -czf dist.tar.gz -C ruoyi-ui dist
scp dist.tar.gz cloudweb@101.201.244.231:/tmp/

# 2) 服务器上解包、备份、替换
ssh cloudweb@101.201.244.231
cd /opt/cloudweb/manager
rm -rf /tmp/manager_dist && mkdir -p /tmp/manager_dist
tar -xzf /tmp/dist.tar.gz -C /tmp/manager_dist

mv dist dist_bak_$(date +%y%m%d_%H%M)     # 备份旧版本（注意现网已有 dist_260805、dist_app，避免重名）
mv /tmp/manager_dist/dist dist
```

- 静态文件替换**无需** reload Nginx（路径不变）。
- `/opt/cloudweb/manager/dist_app` 是历史遗留的旧版 App/移动端产物，不属于本仓库发布范围，不要动。

### 4.3 验证

- 浏览器打开 https://manager.xiaomabiji.com ，`Ctrl+F5` 强刷；确认登录、验证码、菜单、列表接口正常（Network 中 `/prod-api/` 请求 200）。

### 4.4 回滚

```bash
cd /opt/cloudweb/manager
mv dist dist_failed_$(date +%y%m%d_%H%M)
mv dist_bak_YYMMDD_HHMM dist
```

## 5. 官网（xmbj-www-ui，Nuxt 4）

### 5.1 本地构建（静态生成）

```bash
cd xmbj-www-ui
pnpm install
pnpm generate        # 静态生成，产物在 dist/（200.html / 404.html / _nuxt / 各路由目录）
```

注意事项：

- 接口基址在 `app/utils/api.ts` 中硬编码为 `https://www.xiaomabiji.com/prod-api`，若接口域名有变需先改此处再构建。
- 页面数据均为浏览器端请求（未使用 `useFetch`/`useAsyncData`），构建过程**不需要**访问生产接口/数据库。
- 构建机 Node 需 ≥ 20.19（Nuxt 4 要求）。

### 5.2 上传与发布

```bash
# 1) 本地打包并上传
tar -czf www-dist.tar.gz -C xmbj-www-ui dist
scp www-dist.tar.gz cloudweb@101.201.244.231:/tmp/

# 2) 服务器上解包、备份、替换
ssh cloudweb@101.201.244.231
cd /opt/cloudweb/www
rm -rf /tmp/www_dist && mkdir -p /tmp/www_dist
tar -xzf /tmp/www-dist.tar.gz -C /tmp/www_dist

mv dist dist_bak_$(date +%y%m%d_%H%M)     # 备份（现网已有 dist_20260805、dist_260808、dist_260827、dist_bak，避免重名）
mv /tmp/www_dist/dist dist
```

**重要：** `/opt/cloudweb/www` 目录下除 `dist` 外还有：

- `.well-known/`（iOS 通用链接 `apple-app-site-association` 等，App 跳转依赖，**误删会影响 App 链接唤端**）；
- `xm-arts/`（白板前端）、`excalidraw-room-master/`（协作服务）。

因此**只替换 `dist` 子目录**，不要整目录覆盖，也不要使用 `rsync --delete` 同步到 `/opt/cloudweb/www`。

- `curl -I https://www.xiaomabiji.com/.well-known/apple-app-site-association` 返回 200。
- Nginx 中 `/mobile/` location 为历史遗留路径，当前站点已无 `mobile.html`，无需关注。

## 6. Nginx / 域名 / 证书（现状参考）

- 站点配置：`/etc/nginx/sites-enabled/cloudweb.conf`，含三个 server 块：
  - `xiaomabiji.com` / `www.xiaomabiji.com` → `/opt/cloudweb/www/dist`
  - `manager.xiaomabiji.com` → `/opt/cloudweb/manager/dist`
  - `xm-arts.xiaomabiji.com` → `/opt/cloudweb/www/xm-arts/build`（白板前端，非本仓库）
  - 三者均将 `/prod-api/` 反代到 `http://127.0.0.1:8080`。
- 证书：Let's Encrypt（certbot 管理），路径 `/etc/letsencrypt/live/xiaomabiji.com/`，自动续期。
- `cloudweb` 用户无免密 sudo：**仅发布静态文件不需要动 Nginx**；需要改配置/重载时由运维执行：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 8. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 后端启动后立刻退出 | 看 `/opt/cloudweb/server/nohup.out` 末尾；常见原因：jar 上传不完整（对比本地文件大小，约 157MB）、数据库连不上、端口被占用 |
| 重启后在别的目录生成了 `data/` 空目录，白板数据"消失" | 说明 `start.sh` 未在 `/opt/cloudweb/server` 目录下执行；把 `data/` 内容合并回 `/opt/cloudweb/server/data` 并正确重启 |
| 管理后台登录 404/502 | 确认后端 8080 已起来（`ss -lntp \| grep 8080`）；Nginx `/prod-api/` 已配置反代，无需额外操作 |
| 官网上线后部分页面 404 | 确认 `dist` 完整解包（含各路由目录与 `_nuxt`）；检查是否误把 `dist` 内容套了一层目录 |
| iOS 打开 App 链接异常 | 检查 `/opt/cloudweb/www/.well-known/apple-app-site-association` 是否被误删 |
| 服务器重启后接口全部不可用 | 后端非 systemd 托管，需手动执行 `/opt/cloudweb/server/start.sh` |
| `npm run build:prod` 报 OpenSSL 错误 | 见 4.1，加 `NODE_OPTIONS=--openssl-legacy-provider` 或使用 Node 16 |
